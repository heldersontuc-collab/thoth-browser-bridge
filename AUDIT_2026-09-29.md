# Auditoria ponta a ponta — 2026-09-29

## Escopo

Auditoria do caminho completo:

ChatGPT -> GitHub -> THOTH Browser Bridge -> API THOTH Browser Node -> Chromium persistente -> Tailscale -> acesso humano.

Tambem foi revisado o pacote THOTH Browser Node V1.2.1 e o inventario da VPS coletado antes da instalacao.

## Achados principais

### CRITICO — Browser humano ficou publico ao ativar Funnel na mesma porta 443
O Tailscale trata Serve/Funnel por porta. Ao habilitar Funnel em 443, a configuracao existente de Serve em 443 ficou publica junto. O painel raiz foi confirmado acessivel externamente.

Correcao arquitetural: navegador humano em Serve privado numa porta separada (8444); Bridge cifrado em Funnel 443 somente no caminho /thoth-bridge.

### ALTO — healthz provava processo, nao o fluxo real
O Bridge respondia /healthz mesmo sem provar:
- leitura da fila GitHub;
- autenticacao na API do Browser Node;
- execucao de tarefa;
- geracao de resultado.

Correcao: adicionar /readyz que valida poller + API autenticada antes de considerar o Bridge pronto.

### ALTO — fila nao concluiu o primeiro teste fim a fim
Um primeiro probe antigo era criptograficamente invalido. Depois foi criado um probe valido e, mesmo assim, nenhum resultado apareceu. Portanto o poller/queue continua sem prova fim a fim e deve ser diagnosticado antes de liberar operacao real.

### ALTO — Bridge recebia segredos demais
O compose do Bridge importava o .env inteiro do Browser Node, incluindo credenciais que o Bridge nao precisa.

Correcao: fornecer apenas THOTH_API_KEY explicitamente.

### ALTO — Bridge rodava como root por workaround
O workaround de permissao fez o processo voltar a root.

Correcao: runtime nao-root 65532, volume /data com ownership correto, rootfs read-only, cap_drop ALL e no-new-privileges.

### MEDIO — Swagger/OpenAPI estavam publicos
O Funnel expunha /docs e /openapi.json.

Correcao: desabilitar docs/redoc/openapi no Bridge publico.

### MEDIO — codigo canonico V1.2.1 diverge do estado da VPS
O Caddyfile do pacote original nao faz rewrite de /api/healthz -> /healthz. A VPS recebeu uma correcao manual, mas o pacote canonico ainda precisa virar uma nova release.

### MEDIO — versao exibida inconsistente
Pacote V1.2.1, mas API informa version 1.2.0.

### MEDIO — testes insuficientes
O pacote V1.2.1 possui um unico teste automatizado principal e ele cobre modo gerenciado, nao o modo de producao compartilhado via CDP.

### MEDIO — imagens Docker flutuantes
Chromium e socat usam latest; Caddy usa tag major. Isso reduz reprodutibilidade.

### MEDIO — recursos da VPS ficaram apertados
Antes do Browser Node, o inventario mostrava ~70,9% de uso de disco. Depois da instalacao, a VPS mostrou ~82% e swap chegou a ~99%. Precisa medir docker system df e docker stats antes de adicionar mais componentes.

### MEDIO — backup contem segredos
O backup do Browser Node inclui .env e a chave de tunnel. O aviso atual menciona cookies/sessoes, mas deve tratar o arquivo como backup de credenciais completas.

### OBSERVACAO — CDP compartilhado amplia superficie
O Chromium usa remote debugging e um proxy interno. Nao ha porta CDP publicada no host, o que e positivo, mas o perfil contem sessoes autenticadas e deve ser tratado como ativo sensivel.

## Pontos aprovados

- API REST do Browser Node exige THOTH_API_KEY.
- Porta da API e MCP nao sao publicadas no host.
- Perfil Chromium persiste em volume.
- Senhas/OTP/cartao sao redigidos/bloqueados nas rotas de automacao.
- Bridge V1 limita operacao remota a leitura/navegacao; click/fill nao estao expostos no adaptador atual.
- Criptografia do envelope usa X25519 + HKDF-SHA256 + AES-256-GCM.
- Default branch atual nao apresentou segredos obvios em busca por API keys, private keys, password, CPF ou tokens.
- Browser Node original compila e o pytest existente passa 1/1.

## Regra daqui para frente

Nao declarar "instalado com sucesso" apenas porque container esta Up ou /healthz responde.

O criterio de aceite passa a ser um teste fim a fim:
1. ChatGPT cria tarefa valida.
2. GitHub publica tarefa cifrada.
3. VPS registra que leu a tarefa.
4. Bridge autentica no Browser Node.
5. Chromium executa uma leitura publica.
6. resposta cifrada fica disponivel.
7. ChatGPT recupera e descriptografa a resposta.
8. navegador humano continua inacessivel pela internet publica.

So depois dos oito itens passarem a ponte sera considerada pronta.
